2026-11-models

Which model should do each kind of work: planning, Python, Swift, a website?

Candidates: the local models on Adlerbot, run by Hermes. Sonnet and Terra (cloud) are for comparison only.

The tests

TestWhat the model doesPasses when
GateLoads and answers on AdlerbotLoads at 64K context, 20 of 20 tool calls parse, 15 tok/s or faster
1 · PlanningPlans the house-cleaning problem with SpecKit: spec, plan, tasks, estimateEvery document complete, open questions listed in questions.md, and the blind review finds the plan fit to build both apps from
2 · PythonBuilds the desktop app, a local web page, from the best local plan, one milestone at a timeEvery milestone passes its hidden tests, earlier milestones' tests included
2 · SwiftBuilds the mobile app's logic, a Swift package with no screens, the same waySame as Python
WebsiteBuilds a site from the owner's brief and imagesThe owner judges it against his own site

Why this way

  • One problem, written with the owner. The test measures planning, not guessing what the problem is.
  • Finished first, then quality. Unfinished or unusable work doesn't help. Speed only breaks ties.
  • Each test drops models. Time goes to the models that could be chosen.
  • Three runs each. One run can be luck. A model needs 2 of 3; a gap smaller than a model's own run-to-run spread is a tie.
  • Crashes don't count. If Hermes or the model server breaks, it is repaired and the work resumes.
  • Graded blind. Graders don't see model names. Hidden tests check only what the plan says.
  • One plan for all builds. So builds compare models, not plans. Cloud models also build their own plan.

Reading the results

complete
Finished and usable.
failed
Finished but not usable. F-numbers (F1, F2…) name the checklist items it misses.
incomplete
Stopped before the end; the cell says where.
machine fault
Broke for a reason that isn't the model's; redone.
#n of N
Rank among finished runs; #1 is best.
2/3
Complete runs out of runs done; the server that ran them is under it.
own / local plan
A cloud model's build cell is split: its own plan above, the local plan below.
not needed
A cloud model skips run 3 when runs 1 and 2 agree.

2026-10-config

Which local setup (engine, model, quantization, thinking, harness) can do planning and real Python and Swift builds?

The tests

TestWhat the model didPassed when
GateLoaded and answered on AdlerbotLoaded at 64K context, 20 of 20 tool calls parsed, 15 tok/s or faster
1 · PlanningTwo proposals, then spec, plan and tasks for two small appsEvery document complete, and the blind review found it fit to send
2 · PythonBuilt an expense tracker in 6 milestonesEvery milestone passed its hidden tests, earlier ones included
2 · SwiftBuilt a habit-tracking package in 5 milestonesSame as Python

Why this way

  • Each test dropped setups. The pick came from whichever survived.
  • Finished first, then quality. Speed only broke ties.
  • Production as the reference. Every model ran with production's settings (thinking off, Hermes at 64K), so a difference is the model's.
  • Three runs each. A setup needed 2 of 3; run 3 ran only when runs 1 and 2 disagreed.
  • Crashes didn't count. They were repaired and the work resumed.
  • Hidden checks. Models never saw the tests or rubrics.

Reading the results

complete
Finished the whole piece of work.
failed
The model's own failure: failed a check, stopped, or ran out of time.
machine fault
Broke for a reason that isn't the model's; redone.
